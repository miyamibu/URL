# Android / iPhone ホームメニューと背景の実装ブリーフ

## Goal

ユーザーが採用した `hamburger-3-models/hybrid-inkling-gpt55/screenshot-full-height.png` の右端・下端まで続くメニューと、同案のベージュ系ホーム背景・中央＋の色を両OSへ反映する。

## Scope and immutable contracts

- 対象は Android/iPhone のホームにある右上メニュー、ホーム背景の色、中央＋の色。保存・検索・表示モード・選択・プロフィール・使い方・データの取り扱いの処理と遷移、カード、タグ、下部5アクションの位置・サイズ・順序は維持する。
- メニューは右上の検索のさらに右のボタンから開き、ヘッダー下から右端・画面下端まで濃色面を表示する。左側のみ暗幕越しにホームを見せる。外側タップと既存項目の選択で閉じる。
- 現在の指定によるメニュー4項目は「プロフィール」「画像なし表示に切り替える／画像つき表示に切り替える」「選択」「使い方」。「データの取り扱い」はメニューに表示しないが、画面や保存データは削除しない。
- `使い方` は説明一覧。オンボーディングを開かない。検索はメニュー外、AIは下部5アクションとは別の導線。
- URL/DB/worker/同期/課金/ナビゲーションの契約は変更しない。実機データの消去を伴うテスト、アンインストール、初期化は行わない。

| --- | --- | --- |

| メニュー面 | `#1C2030` | 右端・下端に密着した面 |
| メニュー文字 | `#FFF9EE` | 4項目と見出し |

| 背景の暗幕 | `#131622`、不透明度37% | ヘッダーより下。右上ボタンは操作可能に保つ |
| 中央＋ | `#B57C3C` | ボタンの色のみ。寸法・位置・押下処理は維持 |

## Platform behavior

- Android は既存 Compose の `UrlSaverRoot.kt` でホーム内にメニューを重ねる。iOS は `RootView.swift` のホーム内に重ねる。OS別のSafe Area/ナビゲーションバーを使い、右端・下端に空白を残さない。
- メニューを開いても検索と右上ボタンの位置関係を保持し、右上ボタンで閉じられる。画面幅が小さい端末では幅を画面から左側の操作余白を引いた値に抑え、長い表示切替文言を読めるようにする。
- 空・取得中・失敗・重複・オフライン・認証・削除Undoなどホームの既存状態は見た目以外変更しない。背景とメニューはそれらの状態でも同じレイヤーに表示する。
- 手動の「使い方」説明一覧などホーム以外の面には元の背景と文字色を残す。ホームのベージュによる文字の低コントラストを持ち込まない。
- 下部「エクスポート」は省略や改行をせず、1行で全文が読めるよう当該ラベルだけ幅に応じて縮める。下部5アクションの位置・処理は変えない。
- 拡大文字時は4項目をスクロールで確認でき、項目や右上ボタンのタップ領域と読み上げ名を維持する。色だけで状態を示さない。
- 手動追加画面の小さな「＋」は、押下先を変えずに高さ56以上の「タグを追加する」文字ボタンへ変更する。

## Validation

- 変更前後に `python3 scripts/verify_mobile_ui_contract.py`。Android/iOSの関連ビルドと必要な静的確認を実行する。
- 実機では canonical Android `jp.miyamibu.urlalbum` と iPhone `com.mibu.codebridge.ios` を確認する。Androidはデータ保持を証明できる手段だけ、iPhoneはAppium/WDAで画面と操作を証明する。
- 両実機でホーム通常・メニュー開・右上ボタン閉・4項目の視認性・背景色・中央＋の色・検索と下部5アクションの位置、手動追加画面の「タグを追加する」の大きさと押下先を目視する。実機証拠が得られない項目は未検証と明記する。
