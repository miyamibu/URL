# ハンバーガーメニュー比較用ブリーフ

## Goal

りんばむのホームでハンバーガーボタンを押した状態について、3モデルが独立して実装したデザイン案を同一条件で比較する。

## Context

- Android は `UrlSaverRoot.kt` の `DropdownMenu`、iOS は `RootView.swift` の `MainTopMenu` が現行実装。
- 比較成果物はブラウザで動く独立したUIプロトタイプ。ネイティブアプリ本体のコード、状態、保存データは変更しない。
- 表示領域は各案とも **390 × 844 CSS px**。メニューを開いた状態で撮影する。

## Preserved contract

- メニュー項目は `プロフィール`、現在の表示モードに応じた `画像なし表示に切り替える`、`選択`、`使い方`、`データの取り扱い` の5つ。新たな機能を足さない。
- ハンバーガーボタンは現行Android/iOSと同じホーム上部の**右端**に置き、その左に検索を置く。メニュー開状態の画像でも右上の位置関係を確認できるようにする。
- `使い方` は説明一覧を指し、初回オンボーディングを指さない。
- ホーム上部の検索はメニュー外。下部は `グループ`、`エクスポート`、中央 `＋`、`タグ`、`アーカイブ` の5アクション。
- `AI` は独立導線。メニュー内や下部の6番目には加えない。
- 項目は押せることが見た目で分かり、タップ領域、文字の読みやすさ、アクセシビリティ名を確保する。

## Prototype implementation

- 各モデルは自分の `index.html` だけを編集する。HTML/CSS/最小限のJavaScriptを1ファイルに含め、外部依存を増やさない。
- 起動時はメニュー開状態。メニューボタンを押すと開閉し、Escape と外側のクリックでも閉じる。
- 内容はダミーのURLカードで再現し、実データを含めない。項目押下はプロトタイプ内で分かる反応を示し、実アプリの機能が動くと誤認させない。
- 3案はそれぞれ独自のレイアウト・階層・余白・配色を提案する。ただしりんばむの軽快なユーティリティアプリとしての品位を保つ。

## Validation

3ファイルそれぞれで5項目、検索、下部5項目、メニュー開閉を点検する。同じブラウザ、同じ390 × 844 viewport、同じ拡大率でスクリーンショットを保存し、比較表示する。ネイティブUIや実機での動作確認とは区別する。
